# Plan — Web-UI (React/TypeScript)

> Code-Task-Flow, Phase 1 · Strang 6 von 6 (siehe `architecture.md` §8.1).
> Living document. Erstellt: 2026-05-21 19:45 · Branch: `claude/plan-project-VQ7T4`

## Ziel / Completion-Condition

Eine bedienbare Web-UI fuer Login, Persona- und Playbook-Verwaltung gegen die
Who2Be-REST-API. Messbar erfuellt, wenn:

- Login ueber `@supabase/supabase-js` (`signInWithPassword`); die Session
  liegt **nur im Speicher** (kein `localStorage`).
- Personae und Playbooks lassen sich listen, ansehen, anlegen und
  aktualisieren; Versionshistorie wird angezeigt; Playbooks lassen sich mit
  einer Persona verknuepfen.
- Alle API-Aufrufe tragen das Supabase-JWT als `Authorization: Bearer`.
- `npm run lint`, `npx tsc --noEmit`, `npm test` ohne Findings.
- Vitest deckt API-Client, Session-Kontext und die zentralen Seiten
  (verhaltensorientiert, gemockte `fetch`/Supabase) ab.

## Quelle / verbindlich

`architecture.md` §4 (`apps/web`), §5 (Auth: Web → Supabase-JWT); Skill
`react-conventions`; API-Endpunkte/-Formen aus den Straengen 2–4.

## Scope

Login + voller CRUD fuer Personae und Playbooks inkl. Versions-Anzeige und
Persona-Playbook-Verknuepfung. Token-Endpunkte (`/v1/tokens`) sind **nicht**
Teil der UI (Agenten-Belang, kein MVP-Web-Feature).

## Entscheidungen

- **`react-router-dom`** fuer die Navigation (Liste ↔ Detail per URL) — neue
  Dependency; ohne Router wuerde Detail-by-id unsauber ueber lokalen State
  laufen.
- **`@supabase/supabase-js`** mit `persistSession: false`,
  `autoRefreshToken: false` — die Session lebt nur im React-State
  (`SessionContext`), nichts im `localStorage` (react-conventions).
- **Kein Server-State-Framework** (kein react-query) — Daten-Fetching ueber
  schlanke Custom-Hooks (`usePersonas` etc.); haelt die Dependencies klein
  („Funktion vor Schoenheit").
- **TypeScript-Typen handgepflegt** in `api/types.ts`, spiegeln die
  Pydantic-Modelle — kein Cross-Language-Typgenerator (out of scope).
- **`config.ts`** liest `VITE_API_BASE_URL`, `VITE_SUPABASE_URL`,
  `VITE_SUPABASE_ANON_KEY`.
- Edit erzeugt serverseitig eine neue Version (`PUT`) — die UI macht keinen
  Diff, sie sendet den vollen Inhalt.

## Komponenten (`apps/web/src/`)

- `config.ts` — Env-Zugriff (`VITE_`-Variablen), an einer Stelle gebuendelt.
- `lib/supabase.ts` — Supabase-Client (`persistSession: false`).
- `api/types.ts` — TS-Typen: `Persona`, `PersonaVersion`, `PersonaContent`,
  `Playbook`, `PlaybookVersion`, `PlaybookContent`, Request-Formen.
- `api/client.ts` — `fetch`-Wrapper; nimmt das JWT, setzt den Bearer-Header,
  mappt Fehlerstatus auf `Error`. Funktionen fuer Personae-/Playbook-CRUD,
  Versionen und die Verknuepfung.
- `auth/SessionContext.tsx` — Context + `useSession`-Hook: haelt JWT/User,
  `signIn`/`signOut` ueber Supabase.
- `auth/RequireAuth.tsx` — Route-Guard; ohne Session → `/login`.
- `hooks/usePersonas.ts`, `hooks/usePlaybooks.ts` — Daten-Fetching pro
  Aggregat (Laden, Fehler, Refetch).
- `pages/LoginPage.tsx` — E-Mail/Passwort-Formular.
- `pages/PersonasPage.tsx` — Liste + Anlegen.
- `pages/PersonaDetailPage.tsx` — Ansehen/Bearbeiten, Versionshistorie,
  verknuepfte Playbooks setzen.
- `pages/PlaybooksPage.tsx` — Liste, Tag-/Trigger-Filter, Anlegen.
- `pages/PlaybookDetailPage.tsx` — Ansehen/Bearbeiten, Versionshistorie.
- `App.tsx` — Router + Provider; `main.tsx` weitgehend unveraendert.
