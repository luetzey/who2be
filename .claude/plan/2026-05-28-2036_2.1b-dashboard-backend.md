# Plan: Phase 2.1b-B — Dashboard-Backend

## Context

Phase 2.1b-A (Prompt 0) ist gemergt: `persona_version.status`,
`playbook_version.status` (Migration 0011) sowie die `status_history`-Tabelle
(0012) existieren. Pydantic-Modelle (`who2be_models.dashboard.DashboardResponse`,
`StatusHistoryEntry`, `VersionStatus`) sind ebenfalls schon da.

Dieser Plan liefert das **read-only Dashboard-Backend**:
`GET /v1/workspaces/{workspace_id}/dashboard`. Schreibender Status-Code
(Transition-Endpoints, Promotion-Logik) ist Prompt A und nicht Teil dieser
Aenderung — dieser Endpoint liest nur und ueberlebt einen leeren
`status_history`.

Plan-Referenz: `.claude/plan/2026-05-27-1921_phase-2-vollwertige-app.md`
§2.1.E.

## Scope (in)

1. **Repository** `apps/api/src/who2be_api/repositories/dashboard_repository.py`
   - Zwei Aggregat-Queries (Persona-Distribution, Playbook-Distribution) via
     `GROUP BY status` auf `*_version` ueber JOIN auf das Entitaets-Aggregat
     (workspace_id-Filter dort).
   - Activity-Feed: `SELECT … FROM status_history WHERE entity_id IN (…ws_id)`
     LIMIT 50 ORDER BY `changed_at DESC`.
   - Protocol + Pg-Impl analog `persona_repository.py`.
2. **Service** `apps/api/src/who2be_api/services/dashboard_service.py`
   - Repository-Aufrufe parallel (`asyncio.gather`) und Mapping in
     `DashboardResponse`. KPIs werden aus der Distribution abgeleitet
     (`active_personas`/`active_playbooks` = `*.active`; `pending_reviews` =
     `persona.review + playbook.review`).
3. **Router** `apps/api/src/who2be_api/routers/dashboard.py`
   - `GET ""` mit `WorkspaceContext`-Dependency (wie `personas.py`); kein POST.
   - Eintrag in `main.py` mit Prefix `_WORKSPACE_PREFIX`.
4. **Tests** `apps/api/tests/test_dashboard.py` (integration-Marker, gleicher
   Bootstrap wie `test_personas.py`):
   - Leerer Workspace → KPIs alle 0, Distribution alle 0, `activity = []`.
   - Workspace mit gemischten Status-Personen (Update bumpt Version, DB-
     Invariante "max. 1 Draft" wird respektiert): Distribution stimmt mit
     direktem DB-Insert auf `persona_version`/`playbook_version`-Statusspalten.
   - Cross-Workspace-Isolation: Personas/Playbooks aus Workspace B duerfen im
     Dashboard von A nicht auftauchen (weder KPIs noch Activity).
   - Activity-Leer-Variante: ohne Eintraege in `status_history` liefert der
     Endpoint trotzdem 200 mit leerer Liste (deckt "Prompt A noch nicht
     gemergt" ab).

## Scope (out, NICHT anfassen)

- `routers/personas.py`, `routers/playbooks.py`, deren Services/Repos
  (Prompt A — Status-Transition + Edit-erzeugt-Draft).
- `apps/web/*` (Prompt C — Dashboard-Page).
- Caching/LRU (Plan nennt optional; out of scope hier — keine Premature-
  Optimization).
- MCP-Anpassungen (active-Filter dort) — Prompt A/spaeter.

## Implementierungs-Schritte

1. Plan ablegen.
2. Repository schreiben:
   - Eine SQL fuer Persona-Distribution (`SELECT pv.status, COUNT(*) … GROUP BY
     pv.status`).
   - Eine SQL fuer Playbook-Distribution.
   - Eine SQL fuer Activity:
     ```sql
     SELECT id, entity_type, entity_id, from_status, to_status,
            changed_by, changed_at, note
     FROM status_history
     WHERE (entity_type = 'persona' AND entity_id IN
              (SELECT id FROM persona WHERE workspace_id = $1))
        OR (entity_type = 'playbook' AND entity_id IN
              (SELECT id FROM playbook WHERE workspace_id = $1))
     ORDER BY changed_at DESC
     LIMIT 50
     ```
     Resource folgt in 2.2 — bewusst noch nicht enthalten, dann muss diese
     Query erweitert werden (Kommentar im SQL).
3. Service schreiben — mapped `dict[status, int]` aus Repository in
   `EntityStatusDistribution` mit Default-0 fuer fehlende Statuswerte.
4. Router schreiben + in `main.py` registrieren.
5. Tests schreiben — drei `@pytest.mark.integration`-Cases.
6. `uv run ruff check .` / `uv run ruff format .` / `uv run mypy .` /
   `uv run pytest -q` lokal gruen.
7. Commit `feat(api): Dashboard-Endpoint (Phase 2.1b-B)` + push auf
   `claude/wonderful-sagan-VOYsy`.

## Datenmodell-Mapping

| Response-Feld | Quelle |
|---|---|
| `kpis.active_personas` | `persona_distribution['active']` |
| `kpis.active_playbooks` | `playbook_distribution['active']` |
| `kpis.pending_reviews` | `persona_distribution['review'] + playbook_distribution['review']` |
| `status_distribution.persona` | `EntityStatusDistribution(**persona_distribution_with_defaults)` |
| `status_distribution.playbook` | analog |
| `activity` | `[StatusHistoryEntry.model_validate(row) for row …]` |
