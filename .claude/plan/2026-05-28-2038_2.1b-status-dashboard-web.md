## Architektur-Entscheidungen

**S1 — Status-Konstanten dupliziert pro Feature.** Task verbietet
Cross-Feature-Imports. Identisches `lib/status.ts` in `features/personas/`
und `features/playbooks/`. Drift-Risiko: minimal — beide Files spiegeln nur
das Enum + die Transition-Matrix aus `packages/models` (kuenftig). Beide
werden von denselben Component-Tests abgedeckt.

**S2 — Status-Farben als CSS-Tokens in `globals.css`, im JSX via
`style={{ backgroundColor: 'var(--status-X)' }}`.** Vermeidet die volle
Tailwind-Class-Generierung (waere `@theme inline` plus :root +
data-theme[light|dark] in Light- und Dark-Variante = 4 zusaetzliche Stellen
nur fuer 4 Toentchen). Inline-`style` mit `var(--token)` ist
design-language-konform: kein `#hex`/raw `oklch()` im JSX, Werte leben in
`globals.css`. Genau die §2.4-Klausel ("Erweiterungen werden hinzugefuegt,
wenn ein echter Use-Case auftaucht") — der Use-Case ist da.

**S3 — Bestehende Badge-Variants fuer Status-Badges**:
`active → default`, `review → secondary`, `draft → outline`,
`inactive → outline + text-muted-foreground`. Keine Badge-Komponente-
Aenderung noetig. Stacked-Bar nutzt die OKLCH-Status-Tokens aus S2.

**S4 — `getDashboard()` als Methode auf `Api`-Closure.** `createApi(token,
workspaceId)` bindet die Workspace-ID heute schon im Konstruktor; alle
anderen Methoden bauen den Pfad daraus. Task-Wording „getDashboard(workspaceId)"
interpretiere ich als „getDashboard auf dem aktuellen Workspace" — sonst
braechen wir das Closure-Muster nur fuer diesen Endpoint.

**S5 — Default-Landing Dashboard via doppeltem Redirect.**
`DefaultWorkspaceRedirect` → `/w/{ws}/dashboard` (statt heute
`/personas`). Zusaetzlich eine Index-Route unter `/w/:workspaceId` die auf
`dashboard` redirected, damit auch tiefe Bookmarks `/w/ws-1` korrekt
landen.

**S6 — Status-Felder Persona/Playbook/Versions optional.** Backend (Phase
A/B) ist noch nicht gemergt, also gibt es heute keine `status`-Felder im
JSON. UI faellt sauber zurueck:
- Wenn Versions kein `status` haben: Header bleibt „Aktuelle Version: N"
  (Bestandstests bleiben gruen), Action-Bar wird nicht gerendert.
- Wenn `status` da ist: Header zeigt „Aktive Version: vN · Du bearbeitest:
  vM (Draft)", Action-Bar erscheint mit korrekter Enabled-Logik.
