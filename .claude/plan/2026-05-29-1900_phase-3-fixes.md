## Hintergrund

Beim Live-Smoke nach Phase 3 fiel auf, dass die Dashboard-Activity-Liste
crasht, sobald `status_history`-Eintraege geladen werden. Das Backend
lieferte die rohen `StatusHistoryEntry`-Zeilen
(`from_status`/`to_status`/`changed_by`/…), das Frontend (`ActivityRow.tsx`)
greift aber auf `activity.actor.display_name` zu — Crash mit
`Cannot read properties of undefined (reading 'display_name')`.

## Track 1 — Dashboard-Activity-Shape

### Scope

1. **Neues DTO `DashboardActivity`** in
   `packages/models/src/who2be_models/dashboard.py`:
   - `ts`, `actor: {user_id, display_name}`, `entity_type`, `entity_id`,
     `entity_name`, `event`, `from_version`, `to_version`.
   - `DashboardResponse.activity` traegt jetzt `list[DashboardActivity]`,
     nicht mehr `list[StatusHistoryEntry]`. Audit-Trail-Modell bleibt
     unveraendert (nur fuer Writes).
2. **Repository** (`apps/api/src/who2be_api/repositories/dashboard_repository.py`):
   - Eine UNION-ALL-Query ueber persona/playbook/resource, die Entity-Namen
     mitliefert (LEFT JOIN auf die jeweilige Entity-Tabelle) und per LEFT JOIN
     auf `auth.users` Email + `raw_user_meta_data` heranholt. **Kein N+1.**
   - Repo gibt eine `DashboardActivityRow`-Dataclass zurueck; Mapping ins
     DTO macht der Service.
3. **Service** (`apps/api/src/who2be_api/services/dashboard_service.py`):
   - `_EVENT_MAP`-Konstante mit den fuenf bekannten Uebergaengen
     (`promoted_to_active`, `submitted_for_review`, `rejected`,
     `returned_to_draft`, `deactivated`); Default-Fall `set_to_<status>`.
   - `_display_name`-Fallback-Kette:
     `raw_user_meta_data->>'name'` → Email-Local-Part → User-ID-String.
   - `_entity_name`-Tombstone-Fallback: fehlende Entities tragen den
     `entity_id`-Tail.
4. **Frontend** (`apps/web/src/features/dashboard/components/ActivityRow.tsx`):
   - Defensive Reads via Optional-Chaining (`activity.actor?.display_name`),
     Fallback-String `'Unbekannt'`.
   - `ENTITY_LABELS` um `resource` erweitert.
5. **Types** (`apps/web/src/api/types.ts`):
   - `DashboardEntityType` um `'resource'` erweitert.
   - `DashboardActivity.actor` jetzt optional/nullable, damit Legacy-Payloads
     ohne `actor` typsicher behandelt werden.
6. **Test-Infrastruktur**
   (`apps/api/src/who2be_api/testing/workspace_setup.py`):
   - Stub-Schema `auth.users(id, email, raw_user_meta_data)` wird beim
     ersten `setup_workspace` angelegt (GoTrue-kompatible Spalten-Teilmenge).
   - Neuer Helper `seed_auth_user(user_id, email, name)` schreibt UPSERTs.
