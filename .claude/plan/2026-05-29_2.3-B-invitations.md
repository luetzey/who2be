## Kontext

Schema + Models existieren (Prompt 0). Diese PR bringt die **Backend-Endpoints**
fuer Member-Verwaltung und Workspace-Invitations samt best-effort Mail-Versand
ueber Supabase GoTrue. Das RBAC-Enforcement (Rollen-Gate scharfstellen) ist
formal Prompt A; hier reicht ein funktionierender `require_role(ctx, "admin")`-
Stub, den A spaeter zur vollen Permission-Matrix ausbaut. Der Stub erzwingt
bereits admin-only fuer Management-Endpoints (Test 7).

## Scope / Umsetzung

### 1. `core/security.py` — `require_role` (Stub-Gate)

- Rollen-Rang `viewer<editor<admin`; `require_role(ctx, minimum)` wirft 403,
  wenn `ctx.role` unter `minimum`. Reale, durch A erweiterbare Funktion.

### 2. `repositories/workspace_member_repository.py` (neu)

- Protocol + `PgWorkspaceMemberRepository`.
- `list_by_workspace(workspace_id) -> list[WorkspaceMemberRead]`.
- `update_role(workspace_id, user_id, new_role) -> WorkspaceMemberRead | None`
  — `None` = Member fehlt. Transaktional: ist der Member aktuell `admin`, soll
  herabgestuft werden und ist der **letzte** admin → `LastAdminError`.
- `remove(workspace_id, user_id) -> bool` — analoge Last-admin-Guard.
- `LastAdminError` (Modul-Exception) → Service mappt auf 409.

### 3. `repositories/invitation_repository.py` (neu)

- `create(workspace_id, email, role, token_hash, expires_at, created_by) -> InvitationRead`.
- `list_pending_by_workspace(workspace_id) -> list[InvitationRead]`
  (`accepted_at IS NULL AND revoked_at IS NULL AND expires_at > now()`).
- `accept(token_hash, user_id) -> AcceptResult` — **eine** TX: Row `FOR UPDATE`,
  Zustand pruefen (not_found / gone), `workspace_member` einfuegen
  (`ON CONFLICT DO NOTHING`), `accepted_at = now()`. Single-use durch
  guarded Update.
- `revoke(workspace_id, invitation_id) -> bool` (nur offene Invitations).
- Token-Klartext nie persistiert — nur `hash_token()` (sha256).

### 4. Services

- `services/workspace_member_service.py`: list/update_role/remove,
  `LastAdminError`→409, fehlender Member→404.
- `services/invitation_service.py`: create (Token erzeugen, 7-Tage-Expiry,
  hash, insert, Mail best-effort), list_pending, revoke (404), accept
  (not_found→404, gone→410). Liefert Klartext-Token im Create-Result.

### 5. `routers/members.py` (neu, Workspace-Prefix)

- `GET /v1/workspaces/{ws}/members` — jedes Mitglied.
- `PATCH /v1/workspaces/{ws}/members/{user_id}` — admin-only, Body `{role}`.
- `DELETE /v1/workspaces/{ws}/members/{user_id}` — admin-only.

### 6. `routers/invitations.py` (neu)

- Workspace-scoped Router (Prefix `/v1/workspaces/{ws}/invitations`):
  - `POST` (admin-only) → 201 mit Klartext-Token (`InvitationCreated`).
  - `GET` (admin-only) — pending.
  - `DELETE /{id}` (admin-only) — revoke.
- Anonymer Accept-Router (`/v1/invitations`):
  - `POST /{token}/accept` — `get_current_user` (anderer JWT), setzt
    `workspace_member`, 410 bei accepted/revoked/expired.

### 7. `integrations/gotrue_mailer.py` (neu)

- `send_invitation_email(email, accept_url)` → `POST {supabase_url}/auth/v1/invite`
  mit Service-Key (apikey + Bearer), `redirect_to` zeigt auf
  `{web_base_url}/invitations/{token}/accept`. Best-effort: ohne Config oder bei
  Fehler nur loggen, Invitation bleibt gueltig (ADR 0023; SMTP-Hook bewusst NICHT).
- Config: `supabase_service_key`, `web_base_url`. Dep: `httpx`.

### 8. Models

- `invitation.py`: `InvitationCreated(InvitationRead)` mit `token: str`
  (Muster `TokenCreated`). Export in `__init__.py`.

### 9. `main.py`

- `members.router` + `invitations.router` unter `_WORKSPACE_PREFIX`;
  `invitations_accept.router` top-level (anonymer Accept).

### 10. Tests `apps/api/tests/test_invitations.py`

- Create→Accept E2E (zweiter User), Double-Accept→410, Expired→410,
  Revoked→410, Cross-Workspace-Read isoliert, admin-only Gate (editor→403),
  Member-Liste, Rollen-Update, Last-admin-Self-demote→409.
