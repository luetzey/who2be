## Scope (genau diese Files)

### CSS / Theme

- `apps/web/src/styles/globals.css` — scopede CSS-Regeln fuer BlockNote-
  Insel (h1/h2/h3-Sizes + Popover-Backgrounds fuer Slash-/Side-/Drag-
  Handle-Menus). **Kein** globaler Reset, **kein** Override von
  Tailwind-Preflight. Die Regeln greifen nur unter `.bn-container` /
  `.bn-block-content`.

### BlockNote-Insel-Wrapper

- `apps/web/src/features/resources/components/ResourceEditor.tsx` —
  Wrapper-Klasse `bn-container` aufs Outer-`div`, damit die CSS-Scopes
  greifen. Funktionaler Vertrag unveraendert.

### Persona-Form

- `apps/web/src/features/personas/components/PersonaEditorForm.tsx` —
  Sektionen "Identitaet", "Profil", "System-Prompt", "Tags".
  `properties`/`traits`-Input entfaellt. Die Sektion "Profil" mountet den
  `ResourceEditor` als BlockNote-Insel auf `content.blocks`.
- `apps/web/src/features/personas/hooks/usePersonaForm.ts` — Schema +
  Default-Values + Reset + Submit-Mapping anpassen:
  - `traits` raus aus dem Formular.
  - `profileBlocks: ResourceBlock[]` rein (kein Zod-Validation-Branch —
    BlockNote liefert ein offenes Schema; max-length-Limit ist
    Backend-seitig durch `PersonaContent.blocks max_length=2_000`).
  - `tags: string[]` rein (analog Playbook).
  - Submit: `traits: []` weiterhin senden (PydanticDefault, kompatibel
    mit aktuellem Backend), `content: { description: '', blocks }` als
    neue Schwester-Struktur, `tags: [...]`.

### Playbook-Form

- `apps/web/src/features/playbooks/components/PlaybookEditorForm.tsx` —
  - Typ → shadcn-`Select` mit 6 ENUM-Optionen + Per-Option-Hint
    (`text-xs text-muted-foreground` unter dem Select, wechselt nach
    Auswahl).
  - Inhalt → BlockNote-Editor (gleicher Wrapper wie Persona).
  - Tags → `TagInput` mit DISTINCT-API-Vorschlag.
  - Triggers bleibt CSV.
  - FormSections "Identitaet" + "Inhalt"; jede mit konkretem Beispiel-
    Hint.
- `apps/web/src/features/playbooks/hooks/usePlaybookForm.ts` —
  - Schema: `tags: string[]` statt CSV-`string`.
  - `body` wird zu `ResourceBlock[]` (Backend speichert `body: str`,
    daher wird vor dem Submit auf einen Markdown-aehnlichen Plain-Text
    serialisiert — wir nutzen den bestehenden `blockPlainText`-Helper
    pro Block, joinen mit `\n\n`).
  - `type: PlaybookType`.

## Risiken / Offene Stellen

- TagInput-Vorschlag laeuft gegen Backend, das Tag-Endpoint nicht
  liefert → Empty-Fallback bewusst, kein User-sichtbarer Fehler. Wenn
  Track A merged ist, ist der Endpoint da, ohne Frontend-Aenderung.
- Playbook-Body Backend-Schema: `body: str` (max 50k) im Backend. Bei
  BlockNote-Wechsel persistieren wir den Plain-Text-Snapshot der
  Bloecke, damit Backwards-Compat bleibt. Round-Trip (BlockNote →
  Plain-Text → BlockNote) ist verlustbehaftet — fuer dieses PR
  pragmatisch akzeptiert; ein spaeterer Migration-Schritt
  (`PlaybookContent.body_blocks`) folgt in einem eigenen Plan.
- ResourceLink.available_in optional in TS — Backend liefert das Feld
  erst mit Track A. Frontend liest beides (alt + neu), gruenes Build
  garantiert.
