## Kontext

Phase 2 ist auf `main` und fachlich vollständig (Tenancy + Status + Resources +
RBAC), aber der manuelle Smoke gegen die laufende App hat 16 konkrete UX-
Findings produziert. Sie fallen in vier disjunkte Themen — Layout-Navigation,
Editoren/Forms, Status-Flow-Sichtbarkeit und Invitations-Onboarding. Daraus
wird Phase 3 als Polish-Sprint.

Kein neuer Migrations-Stack nötig außer einem ENUM-Set für `playbook.type`
und einem Status-Default-Fix für neue Versionen. Kein neues ADR.

## Architektur-Entscheidungen (Phase 3)

Werden pragmatisch fixiert; wenn der User vor Track-Start Veto einlegt, sind
sie in einem 30-min-Re-Plan korrigierbar.

| Thema | Entscheidung |
|---|---|
| Persona-Inhalt | `properties` (CSV) entfällt; neues `content: BlockNoteDoc` als optionales Feld für strukturierte Persona-Beschreibung (Rolle, Tonfall, Beispiele). `system_prompt` bleibt Textarea (technischer Prompt). `description` bleibt `Input` (Einzeiler für die Liste). |
| Persona-Tags | Neu: optionales `tags: list[str]` als Schlagworte (analog Playbook). |
| Playbook-Type | Curated ENUM `{prompt, instructions, snippet, workflow, checklist, faq}`; UI-Select; Migration setzt CHECK-Constraint. |
| Tag-Multi-Select | UI lädt bisherige Tag-Werte via `GET /tags?entity=…` (DISTINCT-Query); Pill-Picker mit „Tag erstellen"-Suggestion bei nicht-Match. |
| Block-Ref-Section | Picker zeigt **nur Heading-Blöcke**; gespeichert wird der Heading-`block_id`. Preview rendert die Section (Heading bis nächstes Heading desselben Levels) serverseitig im Plain-Text. Datenmodell unverändert. |
| Available-Fallback | Wenn Resource keine Active-Version hat, fällt der Match auf die aktuelle (draft) Version zurück; UI zeigt Badge „Nur in Draft" statt „Verfügbar". |
| Status-Default | Neue v1 startet als `status='draft'` (statt heute `'inactive'`). Migration backfilled bestehende v1-mit-`inactive`-und-ohne-Active-Schwester auf `'draft'`. |
| Invitation-Accept | GoTrue-Magic-Link statt eigener Signup-Bridge: Backend versendet `invite`-Mail mit `redirect_to=/invitations/{token}/accept`; GoTrue legt User an + setzt Passwort, Re-Direct landet bereits eingeloggt auf der Accept-Page. |

## Track D — Invitation-Onboarding (Magic-Link)

**Branch:** `feat/3-D-invitation-magic-link`
**Vorbedingung:** Track 0 gemerged.
**Parallel zu:** A/B/C möglich (komplett eigenes File-Set, außer InvitationAcceptPage).

### Scope

1. **Backend `invitation_service.create`:**
   - GoTrue-Wrapper umstellen: statt `POST /auth/v1/invite` mit beliebigem
     `redirect_to` jetzt `redirect_to={WEB_BASE_URL}/invitations/{token}/accept?via=magic`.
   - GoTrue erstellt User (oder findet bestehenden), schickt Magic-Link-Mail.
   - Klartext-Token bleibt im 201-Body — als Fallback für manuelles Teilen.

2. **Backend `POST /v1/invitations/{token}/accept`:**
   - Bisher fordert er `Authorization`-Header (eingeloggter User). Bleibt so.
   - Neuer Validation-Check: Wenn `accept_router.dependencies` einen User
     ohne `email`-Bestätigung kriegt, wird die Mail-Adresse aus dem JWT mit der
     `workspace_invitation.email` verglichen — bei Mismatch 403 mit Microcopy
     „Diese Einladung ist für eine andere Email-Adresse.".

3. **Frontend `InvitationAcceptPage`:**
   - Bei `?via=magic`-Query: andere Microcopy — „Du wirst angemeldet…", nach
     erfolgreichem GoTrue-Magic-Link landet die Page bereits eingeloggt, ruft
     dann automatisch `acceptInvitation` (kein „Annehmen"-Button mehr).
   - Bei direktem Aufruf ohne `?via=magic` (manuelles Token-Teilen): bestehender
     Flow (Login-Redirect mit `?next=`).
   - Fehler-Microcopy für Email-Mismatch (403) hinzufügen.

4. **Login-Page `?next=`-Sicherheit:**
   - Heute übernimmt `LoginPage` `?next` ungeprüft. Validation einbauen:
     `next` muss mit `/` beginnen und darf kein `//` enthalten (Open-Redirect-
     Verhinderung).

### Tests

- Backend: `test_invitations.py` ergänzen — `redirect_to`-URL-Format, Email-
  Mismatch-Pfad.
- Frontend: `InvitationAcceptPage.test.tsx`:
  - `?via=magic` + eingeloggter User → Auto-Accept ohne Klick.
  - Manueller Aufruf ohne `?via` + nicht eingeloggt → Redirect mit `next`.
  - 403 zeigt Email-Mismatch-Microcopy.
- `LoginPage.test.tsx`: `next=//evil.com` wird ignoriert.

### Deliverable

PR `feat(api,web): Phase-3-D — Invitation-Magic-Link + Onboarding-Bridge`.
