### Task 2 — C5a: Local-Encrypted-Dump

**`deploy/hetzner/scripts/backup.sh`** — neu, `set -euo pipefail`:
1. Pflicht-Env: `POSTGRES_HOST`, `POSTGRES_DB`, `POSTGRES_USER`,
   `PGPASSWORD`, `BACKUP_GPG_RECIPIENT`, `BACKUP_DIR=/var/backups/who2be`.
2. Timestamp `ts=$(date -u +%Y%m%dT%H%M%SZ)`.
3. `pg_dump -Fc -h "$POSTGRES_HOST" -U "$POSTGRES_USER" "$POSTGRES_DB" \
   | gpg --batch --yes --trust-model always -e \
   -r "$BACKUP_GPG_RECIPIENT" -o "$BACKUP_DIR/dump-$ts.pgc.gpg"`.
4. `find "$BACKUP_DIR" -name 'dump-*.pgc.gpg' -mtime +7 -delete`
   (lokale Retention; offsite uebernimmt restic).
5. Logging via `echo "[backup] ..."` auf stdout fuer Container-Logs.

**Compose-Service** (`deploy/hetzner/who2be/docker-compose.yml`) —
neuer Service `backup` mit:
- `profiles: ["backup"]` (manuell oder cron-getriggert, nicht im
  Default-up).
- `build` lokales Dockerfile `deploy/hetzner/backup/Dockerfile` (neu):
  `alpine:3.20`, installiert `postgresql16-client`, `gnupg`, `restic`
  (vorbereitend fuer C5b), `openssh-client`. Entry `/scripts/backup.sh`.
- `volumes`: `backups:/var/backups/who2be`, `./scripts:/scripts:ro`,
  Secrets via `./secrets:/secrets:ro` (GPG-Public-Key, SSH-Key).
- `env_file: ../.env`.
- `networks: [app-net, supabase-net]` (kommt an `db`).
- `depends_on: [migrate]`.
- Top-Level `volumes:` um `backups:` ergaenzen.

**`deploy/hetzner/.env.example`** — neue Sektion `# Backup (C5a/C5b)`:
- `BACKUP_GPG_RECIPIENT=ops@who2be.example`
- (C5b-Vars siehe Task 3)

**Cron-Strategie:** bewusst **Host-Cron**, nicht Compose-Sidecar
(spart Dauerlauf eines Backup-Containers; im RUNBOOK dokumentiert
als `15 3 * * * cd /opt/who2be && docker compose --profile backup
run --rm backup`).

**RUNBOOK-Sektion "Backup & Restore"** (vor "Akzeptierte
Vulnerabilities" einfuegen):
- Setup: GPG-Public-Key importieren (`gpg --import ops-pub.asc`),
  Recipient in `.env`, Backup-Verzeichnis anlegen.
- Trigger: `docker compose --profile backup run --rm backup` manuell;
  Host-Crontab-Eintrag fuer 03:15 UTC daily.
- Verifikation: `ls -lh /var/backups/who2be/` zeigt neuen Dump,
  `gpg -d dump-<ts>.pgc.gpg | head -5` zeigt PostgreSQL-Header.
- Restore: `gpg -d dump-<ts>.pgc.gpg | pg_restore -h db -U postgres
  -d who2be_restore --clean --if-exists`.

### Task 3 — C5b: Offsite-Sync via restic

**`deploy/hetzner/scripts/backup.sh` Erweiterung** — nach erfolgreichem
GPG-Dump:
1. Pflicht-Env: `RESTIC_PASSWORD`, `RESTIC_REPOSITORY` (z.B.
   `sftp:u123456@u123456.your-storagebox.de:/who2be-backup`),
   `RESTIC_SSH_KEY=/secrets/storage_box_ed25519`.
2. `export RESTIC_PASSWORD RESTIC_REPOSITORY`.
3. Bei erstem Lauf (Repo leer): `restic init`. Detect via
   `restic cat config >/dev/null 2>&1 || restic init`.
4. `restic backup "$BACKUP_DIR" --tag dump --host who2be-prod \
   -o sftp.args="-i $RESTIC_SSH_KEY -o StrictHostKeyChecking=accept-new"`.
5. `restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6
   --prune`.
6. Exit-Code aggregieren: GPG-Fehler ist fatal, restic-Fehler wird
   geloggt aber nicht-fatal (lokaler Dump bleibt erhalten).

**`deploy/hetzner/.env.example`** — Backup-Sektion erweitern:
- `RESTIC_PASSWORD=<random-32-bytes>`
- `RESTIC_REPOSITORY=sftp:u123456@u123456.your-storagebox.de:/who2be-backup`
- `STORAGE_BOX_SSH_KEY_PATH=./secrets/storage_box_ed25519`

**RUNBOOK-Sektion "Backup & Restore"** erweitern:
- Offsite-Setup: Storage-Box auf Hetzner anlegen, SSH-Key generieren
  (`ssh-keygen -t ed25519 -f deploy/hetzner/secrets/storage_box_ed25519
  -N ""`), Public-Key im Hetzner-Robot hinterlegen.
- `restic snapshots` Verifikation (juenger als 26h).
- **Restore-Drill** Schritte (zaehlt fuer H4 als Trockenlauf):
  `restic snapshots` → snapshot-id waehlen → `restic restore <id>
  --target /tmp/restore` → `gpg -d /tmp/restore/.../dump-<ts>.pgc.gpg
  | pg_restore ...`. Notiz: H4-Live-Drill bleibt nach C1.

**Lokale Verifikation** (im Plan-Ausfuehrungs-Schritt):
- `export RESTIC_REPOSITORY=/tmp/restic-test RESTIC_PASSWORD=devpw`
- `restic init && restic backup deploy/ && restic snapshots`
- Bestaetigt, dass das Script gegen ein nicht-SFTP-Backend
  funktioniert. SFTP-Backend wird beim C1-Cutover live verifiziert.
