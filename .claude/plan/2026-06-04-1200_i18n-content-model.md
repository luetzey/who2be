## Schritte (nach Freigabe)

1. **Migration 0042 — `locale` + Indizes.**
   - `ALTER TABLE … ADD COLUMN locale text NOT NULL DEFAULT 'de'
     CHECK (locale IN ('de','en'))` auf `persona_version`, `playbook_version`,
     `resource_version`, `system_prompt_template_version`.
   - `(entity_id, version)`-UNIQUE → `(entity_id, locale, version)`.
   - Partial-Unique-Indices `*_active/draft/review_uniq` →
     `(entity_id, locale) WHERE status=…`.
   - Idempotent (Runner via `schema_migrations`). Verifizieren:
     `uv run who2be-migrate` lokal gegen Docker-DB.

2. **Models (`packages/models`).**
   - `ContentLocale = Literal["de","en"]` + `DEFAULT_LOCALE`.
   - `locale` in `*VersionRead`; `locales` in `*Create`; locale-Plumbing in
     Update/Draft (Service-Signaturen).
   - Barrel `__init__.py` Export.

3. **Repositories.**
   - Content-Select auf "neueste Version je (entity, locale)" umstellen
     (statt `version = current_version`); `pv.version AS current_version`
     aliasen.
   - Active-Reads: `AND pv.locale = $locale`.
   - `next_version` pro locale. insert/update/upsert_draft/restore_version
     locale-aware. Audit aller `current_version`-Leser
     (persona/playbook/resource/composition/agent-Repos, persona_playbook).

4. **Services.**
   - Create: pro gewaehltem locale eine Draft-v1 anlegen (Copy der Vorlage).
   - Update/Draft/restore/transition: locale durchreichen, pro (entity,locale).

5. **API-Router** (personas/playbooks/resources + system_prompts).
   - `?locale=de|en` (Default `de`) auf Read-Endpoints; `locales` im POST;
     `?locale=` auf Mutationen.

6. **MCP** (`apps/mcp/server.py`).
   - `locale: str = "de"` an `get_persona`, `fetch_playbook`, `fetch_resource`,
     `list_playbooks`, `list_resources`; als `?locale=` durchreichen;
     weiterhin `status='active'`.

7. **Frontend Create-Flows.**
   - Multi-Select DE/EN in Create-Dialogen → `locales`. Lese-/Editor-Flows
     reichen `locale` durch (D1-Abstimmung; Default `de` bis D1 steht).

8. **Tests + Gates.**
   - Backend: Persona/Playbook/Resource in DE+EN anlegen; API liefert korrekte
     Variante per locale; Default `de` unveraendert; MCP locale-Param.
   - `uv run pytest -q`, `ruff check .`, `mypy .`; `npm run lint`,
     `tsc --noEmit`, `npm test`, `npm run build`.

9. **Draft-PR** mit ADR-Link + Repro/Design-Zusammenfassung.

## Risiken / offene Punkte

- `current_version`-Spalte verliert Auswahl-Hoheit → Bestandscode auditieren.
- Block-Refs (Playbook→Resource) sind locale-blind → in dieser Welle nur
  intra-locale aufloesen; cross-locale out of scope.
- `status_history` ohne locale-Spalte (entity-weit) — bewusst, ggf. spaeter.
- Seed-Daten / Default-Templates (0023b/0027-seed) sind `de` — bleiben gueltig.
