### FAIL-Detail: Tokens anlegen/widerrufen — viewer

Der Test-Plan (`T`) erwartet: **viewer ✓ (≤ eigene Rolle)** für Token-Verwaltung.

Die Implementierung (`_MATRIX` in `test_rbac_matrix.py`):
```python
"create_token": {
    WorkspaceRole.viewer: False,   # 403!
    WorkspaceRole.editor: True,
    WorkspaceRole.admin: True,
},
```
Und `_ACTION_GATE["create_token"] = WorkspaceRole.editor`.

**Beobachtet:** `test_rbac_matrix[create_token-viewer]` → PASS mit Erwartung 403.  
**Test-Plan sagt:** viewer darf Tokens anlegen (≤ eigene Rolle, d.h. viewer-Token).  
**Implementierung/Test-Matrix sagt:** viewer 403.

Dies ist eine **Diskrepanz zwischen Test-Plan (Strang T) und Implementierung + Testmatrix**.  
Die Implementierung ist konsistenter mit ADR-0023 ("Tokens editor+"), der Test-Plan-Text könnte veraltet sein.

**→ Bug/Inkonsistenz FT-T-TOKEN-VIEWER**: Test-Plan-Text (`T`: viewer ✓) vs. Code (`editor` Mindestrolle). Eine der beiden Quellen ist falsch. Im Code wird konsistent `editor` für Token-Create durchgesetzt.
